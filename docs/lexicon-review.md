# Controlled Lexicon Review Infrastructure (`review-decision-v1`)

This document specifies the design, data structures, and operational rules for the Kurmancî controlled lexicon review infrastructure (Milestone 4A.1).

## Architecture Overview

```
Sources (sources.toml)
      │
      ▼
Importer (import-hunspell)
      │
      ▼
Audit (audit-lexicon)
      │
      ▼
Review Infrastructure (generate-review-queues / validate-review-decisions)
      │
      ▼
Controlled Pack Policy & Builds (Milestone 4A.2)
```

## Data Boundaries

1. **Generated Review Queues (`data/review-queues/<source-id>/`)**:
   - Schema: `review-queue-v1`
   - Generated mechanically by `cargo run -p kurmanci-data-builder -- generate-review-queues <source-id>`.
   - Uses atomic staged directory replacement (`.tmp_stage` -> target).
   - Tools may replace this directory. Humans should **NEVER** edit files in `review-queues/`.

2. **Human Review Decisions (`data/review-decisions/<source-id>/`)**:
   - Schema: `review-decision-v1`
   - Store: `data/review-decisions/<source-id>/decisions.jsonl`
   - Read-only for automated tools. Tools **NEVER** modify or rewrite `decisions.jsonl`.
   - Human maintainers add, edit, and maintain decisions in this store.

3. **Controlled Review Reports (`data/reports/controlled-lexicon-review/`)**:
   - Schema: `controlled-review-report-v1`
   - Generated by `cargo run -p kurmanci-data-builder -- validate-review-decisions <source-id>`.
   - Merges human decisions against mechanical queues to produce effective audit reports (`summary.json`, `approved.jsonl`, `metadata-changes.jsonl`, `rejected-from-default.jsonl`, `experimental-only.jsonl`, `unresolved.jsonl`, `orphan-decisions.jsonl`, `artifacts.sha256`).

## Canonical ID Calculation

All `entry_id` and `group_id` SHA-256 hashes use u64 big-endian length-prefixed field encoding (`hash_field(hasher, field)`), returning contextual `Result` errors without `unwrap()` or `expect()`.

### Entry Identity (`kurmanci-review-entry-v1`)
`entry_id` identifies a preserved imported source record. It remains stable across review decisions. Human review metadata never changes the entry identity.

Input fields:
1. Domain prefix: `kurmanci-review-entry-v1`
2. `source_id`
3. `source_revision` (file SHA-256 or commit SHA from `sources.toml`)
4. `display` (Unicode NFC normalized)
5. `normalized` (`normalize_text` pipeline)
6. `flags`
7. Sorted canonical morphology tags

### Conflict Group Identity (`kurmanci-review-group-v1`)
Conflict-group IDs are regenerated from imported data. Human review never edits conflict-group membership; only decisions change.

Input fields:
1. Domain prefix: `kurmanci-review-group-v1`
2. `normalized` (`normalize_text` pipeline)
3. Sorted member `entry_id`s

## Decision Target Uniqueness & Validation Rules

- **Tuple Uniqueness**: The tuple `(target_type, target_id)` MUST be unique across all decision records in `decisions.jsonl`.
- **Target Types**: `"entry"`, `"conflict_group"`.
- **Status Rules**:
  - `unreviewed`: `reviewer_id`, `review_date`, `review_notes` must be `None`.
  - Reviewed statuses (`approved`, `approved_with_metadata_change`, `rejected_from_default_pack`, `experimental_only`, `needs_linguist`, `needs_source_investigation`): Require non-empty `reviewer_id` and valid calendar date (YYYY-MM-DD).
  - `approved`: Prohibits replacement fields.
  - `approved_with_metadata_change`: Requires `replacement_metadata` with normalized form derived consistently from replacement display; at least one field must differ; passes lexicon validation.
  - `rejected_from_default_pack`: Requires `review_notes` or non-empty `evidence`.
